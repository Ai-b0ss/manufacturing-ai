## Функциональность

1. Из существующих трёх точно сопоставленных комплектов P7 извлекаются фактические цифровые PDF и STEP. Хеш SHA-256 каждого файла перепроверяется при запросе. Текстовые обозначения и координаты по P9 привязаны к проверяемому исходному файлу.
2. P11 безопасным короткоживущим подпроцессом PyMuPDF создаёт PNG-фрагмент PDF вокруг надписи, выделяя её красной рамкой, без записи в оригинал. Фрагмент ограничен по числу пикселей, максимальному размеру PDF и времени исполнения. Изображения обслуживаются как приватные ответы HTTP image/png с Cache-Control: no-store, CSRF не нужен для GET. Инженерное ACL проверяется до получения и повторно после обработки.
3. По аналитической STEP-поверхности из P10 показываются тип поверхности, измеренный радиус/угол и исходные индексы граней. Обозначение PDF и поверхность выбираются отдельно: их геометрическая связь **не считается автоматически установленной**.
4. Только учебная роль engineer может сохранять оценку по конкретной паре PDF-надпись/STEP-поверхность: «возможно соответствует», «не тот элемент», «нужны дополнительные доказательства». Требуется обоснование от 12 до 500 символов. Ни одно значение формы не означает принятие к изготовлению или утверждение изменения.
5. Каждая заметка имеет UUID v4 и сохраняется с датой, версией полей, обозначением детали, SHA-256 PDF и STEP, координатами текста, идентификатором поверхности, выбранной осью, описанием решения, ролью автора и ID события.
6. Журнал в data/p11_review.sqlite3 содержит только добавляемые через API события. Транзакции SQLite BEGIN IMMEDIATE, UNIQUE event_id обеспечивают конкурентную запись и идемпотентность; повтор с другим содержимым получает HTTP 409.
7. Записи образуют цепочку SHA-256 по каноническому JSON и предыдущему хешу. Чтение и запись запрещаются при нарушении цепочки. При чтении повторно проверяются исходные файлы: изменённые или отсутствующие источники помечаются SOURCE_CHANGED_OR_MISSING.
8. Сессия, CSRF и инженерная роль проверяются перед записью; после анализа исходника сервер в короткой транзакции приложения повторно проверяет действующие разрешения и блокирует их отзыв до завершения операции записи.
9. Руководитель с учебным правом engineering может читать материалы и журнал, но не записывать заключение от имени инженера. Технолог и финансы не видят приватные материалы; анонимный запрос получает HTTP 401.

## Схема API

GET /api/engineering/p11/preview?q=focuser_drawtube&annotation=<source-bound-id>
— бинарный PNG исходной надписи, с указанием правильного content-type.

GET /api/engineering/p11/findings?q=focuser_drawtube
— история оценок, состояние цепочки, актуальность каждого доказательства.

POST /api/engineering/p11/finding
— JSON {q,annotation,feature,axis,decision,note,event_id}.
Требуется X-CSRF-Token и авторизованная сессия engineer.
Возможные значения decision: PLAUSIBLE_MAPPING, NOT_SAME_FEATURE, NEEDS_MORE_EVIDENCE.

Нет API для утверждения, выпуска, передачи в 1С/PLM, изменения исходных PDF/STEP или финансовой информации.

## Почему это пока учебный журнал, а не юридически значимый аудит

- Аккаунт engineer демонстрационный; он не подтверждает личность конкретного специалиста.
- Цепочка SHA-256 без внешнего доверенного якоря, аппаратного ключа и независимого журнала не гарантирует защиту от администратора, который может переписать все записи или удалить хвост.
- Нет проверки полномочий подписанта, УКЭП, интеграции с PLM/1C, роли второй линии контроля, технологических допусков, соответствия требованиям ЕСКД или применимости к производственной партии.
- Кроп изображения показывает область надписи, но не доказывает связь выноски с выбранной поверхностью. Нет 3-D выделения граней и 2-D → 3-D геометрической регистрации.
- Нет изолированной песочницы ОС для загрузки недоверенных файлов. Обрабатывать секретные корпоративные документы в этом демонстрационном стенде нельзя.

## Исходные данные и инфраструктура

P11 использует те же 40 публичных оригиналов P7, 19 PDF и три реальные CAD-модели из P8. Исходный набор находится в непубликуемой папке проекта P6; копии source PDF/STEP не попадают в Git.

P11 использует локальную изолированную среду OCCT/PyMuPDF через Windows junction к существующей .p8venv P8; файлы среды P8 не менялись. Для независимого запуска нужно создать .p8venv и выполнить установку requirements-cad.txt, затем IMPORT_CORPUS.cmd.

Сценарии:
- START_DEMO.cmd — запуск на localhost:19132, повторный вызов не запускает второй экземпляр.
- OPEN_DEMO.cmd — открыть браузер на самом ПК.
- TEST_DEMO.cmd — полный объединённый набор регрессий P6–P11.
- IMPORT_CORPUS.cmd — атомарный переимпорт индексов P7/P8; отдельно сохраняемые P11-заметки никогда не удаляет.

## Проверка

Тесты: test_visual_review.py; объединённый runner: test_runner.py.
Браузер: p11_browser_harness.py и p11_browser_smoke.cjs.

Браузер проверяет загрузку настоящего PNG-кропа R41.5, запись заметки через браузерный API, идемпотентность, мобильную ширину 390 px, сохранность сценариев P7–P10, отсутствие JavaScript-исключений и запретов производственного допуска.

Снимки: data/p11_engineering_desktop.jpg и data/p11_engineering_mobile.jpg.
Отчёт: data/p11_browser_report.json.
Тестовая база журнала браузера создаётся во временной папке; деможурнал пользователя не засоряется фальшивыми записями тестирования.
