# Цех.Знания · ManufacturingAI

Локальный прототип для поиска по инженерным документам и проверки цепочки редакций. От ответа можно перейти к исходному документу, странице и связанным данным PDF/STEP.

**Статус:** исследовательский прототип. Базовая демонстрация работает на синтетических данных. Защищённый контур v0.6 содержит PostgreSQL RLS, OIDC и гибридный поиск, но весь интегрированный стек ещё не прошёл финальную приёмку. Подключения к промышленным PLM/1С и AD/LDAP не реализованы.

## Быстрый запуск демонстрации

Требуется Python 3.13 с SQLite FTS5. Для базового интерфейса и поиска по встроенным учебным данным внешние пакеты не нужны.

```sh
git clone https://github.com/Ai-b0ss/manufacturing-ai.git
cd manufacturing-ai
python app.py --host 127.0.0.1 --port 19134
```

Откройте http://127.0.0.1:19134/ и выберите учебную роль. База демонстрации создаётся в `data/` при первом запуске. Загрузка PDF/DOCX, OCR, нейросетевая генерация и инженерный корпус требуют дополнительной настройки.

В демонстрации предусмотрен вход без пароля. Используйте только учебные данные и loopback-интерфейс.

## Возможности

- Поиск по доступным документам, ссылки на источники и повторная проверка доступа перед выдачей ответа.
- Загрузка PDF/DOCX/TXT, ограничение размера и объёма обработки; OCR через Windows.Media.Ocr.
- Локальная модель через llama.cpp: структурированный ответ и серверная проверка номеров цитат.
- Проверка согласованности редакций, извещений и партий на синтетических записях.
- Инженерный корпус P7–P13: извлечение выносок PDF, аналитические поверхности STEP, численные кандидаты и визуальные свидетельства.
- Контур v0.6: PostgreSQL RLS, Keycloak OIDC, Qdrant, очередь индексации, контроль оригиналов и инструменты восстановления.

Численное совпадение PDF и STEP не доказывает соответствие конструкции, действительность редакции или разрешение на изготовление. Геометрическая регистрация 2D→3D и проверка GD&T не реализованы.

## Дополнительные компоненты

Для разбора PDF/DOCX:

```sh
python -m venv .venv
# Windows:
.venv\Scripts\activate
python -m pip install -r requirements-documents.txt
```

На Linux/macOS активируйте окружение командой `source .venv/bin/activate`. OCR и ряд служебных сценариев рассчитаны на Windows. Веса модели, llama.cpp, PostgreSQL, Keycloak, Qdrant и исходный инженерный корпус устанавливаются отдельно и в репозиторий не входят.

Настройки локальной модели: `FACTORY_AI_MODEL`, `FACTORY_AI_SERVER`, `FACTORY_AI_PARSER_PY`, `FACTORY_AI_KEY_FILE`. В служебных сценариях защищённого контура сохраняются пути исходного Windows-стенда; перед использованием их необходимо адаптировать. `START_DEMO.cmd` предназначен для исходного стенда с подготовленными индексами; для первого знакомства используйте команду выше.

Для PostgreSQL-адаптера см. `requirements-core.txt`, для STEP/OpenCascade — `requirements-cad.txt`. Модули OIDC и гибридного поиска также требуют FastAPI, Uvicorn, PyJWT, cryptography, Qdrant Client и компонентов эмбеддингов; воспроизводимый установщик всего стека пока не подготовлен.

## Проверки

Базовые проверки HTTP, разграничения доступа, поиска и редакций выполняются без внешних сервисов:

```sh
python -m unittest test_app test_engineering_retrieval test_engineering_evidence
```

Другие тесты требуют дополнительных пакетов, Windows OCR, подготовленного корпуса или изолированных PostgreSQL/Qdrant/Keycloak. Полный `test_runner.py` не является проверкой чистой установки без этих зависимостей.

Результаты проверки публичной копии и границы ранее выполненных испытаний: [docs/VERIFICATION.md](docs/VERIFICATION.md).
Архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
