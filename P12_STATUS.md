## 1. Реальная 3D-геометрия вместо картинки по названию детали

- В P12 используется тот же связанный публичный комплект P7: строка BOM → проверенный PDF → оригинальный STEP. Сервер повторно проверяет SHA-256 оригиналов.
- Группы аналитических граней STEP из P10 имеют ID, вычисляемый из SHA-256 STEP, типа поверхности и канонических числовых параметров. Рендерер заново перечисляет реальные OpenCascade BREP-грани и должен получить ТОЧНО ту же группу; не принимает присланный пользователем список индексов.
- BRepMesh_IncrementalMesh создаёт реальные треугольники поверхностей. Внутри отдельного краткоживущего процесса VTK строит растровое изображение со стандартным Z-buffer, чтобы глубина перекрытия учитывалась. Выбранная аналитическая поверхность — оранжевая; остальные грани — серо-голубые.
- Доступно четыре фиксированных вида: iso, front, side, top. Выбранный фронт/сторона не выводится из PDF-ориентации; это просто ракурсы реальной модели для ручной проверки.
- На интерфейсе рядом остаётся P11 PNG-кроп из настоящего PDF, контекст надписи, SHA-256 PDF и STEP, индексы выбранных CAD-граней и журнал замечаний.
- Ограничения: один STEP до 8 MB, не более 25 000 граней, 350 000 треугольников и 900 000 узлов, 1000×660 px, PNG до 3 MB, subprocess timeout 17 сек, одновременно не более 2 визуализаторов. Доступ: только инженерный ACL, проверка ещё раз после тяжёлого рендеринга.
- Не выполнено: автоматическое геометрическое соответствие PDF-выноски конкретной CAD-грани, 3D-свободное вращение WebGL, проверка размеров отверстий как валидированной размерной цепочки, допуски и посадки, GD&T, утверждение версии и разрешение производства.

### Реальные верифицируемые примеры

1. focuser_drawtube: PDF R41.5 и STEP-группа цилиндрических граней 17, 18, 63, реальный радиус 41.5 мм; подсветка из оригинального BREP. Проверка совпадения чисел не является доказательством назначения размерной стрелки.
2. lower_square_tube: PDF 67.38° и STEP-группа наклонных плоскостей 3, 4, 7, 8, угол к X 67.38015°, разница 0.00015°. Остальные CAD-грани не подсвечиваются.

## 2. Независимый подписанный контрольный снимок журнала

В P11 локальный журнал имеет SHA-256-цепочку записей. При удалении только её последних записей оставшаяся цепочка сама по себе продолжает проходить проверку. P12 допускает независимую проверку исторического префикса журнала по подписанному вне программы контрольному снимку.

**По умолчанию независимый подписант не подключён.** API возвращает NO_EXTERNAL_WITNESS. Это честно отражается в интерфейсе. Без внешнего секрета приложение не подделывает юридическое утверждение.

Получение предложения снимка:
GET /api/engineering/p12/audit
(требуется право engineering; возвращает поле unsigned_checkpoint_proposal)

Содержимое unsigned_checkpoint_proposal:
{
  "schema":"factory-review-checkpoint/v1",
  "store_id":"<UUIDv4 реальной SQLite-базы>",
  "seq":<номер последнего события, 0 для пустой базы>,
  "event_hash":"<SHA-256 последнего события либо 64 нуля>",
  "created_at":"<ISO 8601 UTC ...Z>"
}

Независимая доверенная сторона подписывает только байты canonical JSON:
json.dumps(payload,sort_keys=True,separators=(",",":"),ensure_ascii=False,allow_nan=False).encode("utf-8").
Подпись: Ed25519, 64 байта, base64.
В подписанном JSON два ключа: payload и signature.

Администратор сервера настраивает две переменные окружения:
P12_REVIEW_ANCHOR_FILE — абсолютный путь к созданному независимо подписанному JSON;
P12_REVIEW_ANCHOR_PUBLIC_KEY_HEX — 32 байта доверенного Ed25519-ключа в hex.
Публичный ключ должен закрепляться отдельным организационным процессом, не доверять ключу из самого снимка.

Приложение проверяет Ed25519-подпись, UUID базы, номер записи, точный SHA-256 события на указанной позиции, монотонность последовательности и общую локальную SHA-256-цепочку. Отсутствующий, некорректный или подменённый настроенный снимок приводит к ошибке, а не к молчаливому откату в NO_EXTERNAL_WITNESS. Новый снимок может удостоверять лишь уже существующую историю. Последующие записи после checkpoint явно отмечаются как НЕ подтверждённые внешней подписью.

**Ограничения:** подписанный snapshot сам должен храниться независимо от доступов приложения, а ключ не должен контролироваться оператором этой же базы. Даже валидная криптоподпись сама по себе не подтверждает полномочия юридического подписанта, УКЭП, корректность фактов в заметках, ревизию PLM или пригодность детали к производству. Контрольный снимок не защищает неподписанный хвост журнала от удаления, не исключает несанкционированное отключение конфигурации и не заменяет внешнее неизменяемое хранилище.

## 3. API

GET /api/engineering/p12/render?q=focuser_drawtube&feature=<24 hex>&view=iso
— настоящий PNG, Cache-Control: no-store, только сессия с engineering scope.

GET /api/engineering/p12/feature?q=...&feature=...
— исходный SHA-256 и набор граней CAD (метаданные), manufacturing_authorization=false.

GET /api/engineering/p12/audit
— локальный или независимо подписанный статус цепочки; необработанное предложение нового checkpoint. Не выдаёт секретных ключей.

Протоколы P7–P11 и их защитные ограничения сохранены.

## 4. Запуск и тестирование

START_DEMO.cmd — порт 19133 и проверка версии P12 при повторном запуске.
OPEN_DEMO.cmd — открыть localhost на том самом Windows-ПК.
TEST_DEMO.cmd — полный unittest P6–P12.
IMPORT_CORPUS.cmd — обновить P7/P8-индексы без удаления P11-журнала заметок.

p12_browser_harness.py + p12_browser_smoke.cjs — браузер Chrome headless, реальные PNG, пиксели выделения, переключение вида, журнал, роли, мобильные ширины. Браузерные заметки пишутся в отдельную временную SQLite-базу.
test_cad_visual.py — настоящие OpenCascade BREP, VTK и HTTP.
test_audit_witness.py — Ed25519 подписи, удаление последней записи, переписывание, подмена ключа, замена UUID базы и сохранение недоподписанного хвоста.

Скриншоты и отчёты проверки только локально в data/ — не коммитятся в Git. Оригинальные публичные STEP и PDF остаются в исходном наборе P6.

Ограничения развёртывания: P12 использует локальный Windows junction .p8venv к P8. Для самостоятельной установки создать отдельный venv с пакетами из requirements-cad.txt; конфиденциальные документы не загружать, пока нет корпоративного IAM, контролируемого хранилища, доверенного источника PLM и независимого аудита.
